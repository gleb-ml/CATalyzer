Мы разрабатываем Chrome-расширение Manifest V3 под названием «CATalyze».

СУТЬ ПРОЕКТА:
CATalyze — это ИИ-ассистент в боковой панели (Side Panel). Пользователь выделяет сложный текст на любой странице → вызывает контекстное меню (или шорткат) → текст уходит к выбранному провайдеру LLM (Groq, OpenAI, OpenRouter или кастомный URL) → в панели рендерится упрощенная, легко читаемая выжимка.

ТЕКУЩИЙ СТЕК И АРХИТЕКТУРА:
- Vanilla JS, HTML, CSS (без тяжелых фреймворков вроде React/Vue).
- Side Panel API для основного пользовательского интерфейса.
- chrome.storage.local как единый источник истины (стейт-менеджер для передачи текста между фоном и панелью, хранения ключей, настроек, локализации).
- Прямые асинхронные fetch-запросы к LLM API напрямую из контекста side panel.

ПРАВИЛА БЕЗОПАСНОСТИ И РАЗРАБОТКИ (КРИТИЧНО):
1. **Нулевое доверие к ключам:** Никогда не хардкоди API-ключи, не пиши их в консоль. Ключ должен доставаться из `chrome.storage.local` строго перед самим fetch-запросом и нигде не кэшироваться глобально.
2. **Защита от XSS (Правила MV3):** Запрещено подключать любые библиотеки через CDN (remote code execution запрещен). Все скрипты лежат локально. При рендеринге Markdown в HTML от LLM всегда учитывай уязвимость `innerHTML` — ответ модели должен санитизироваться, чтобы избежать выполнения вредоносного кода со страницы.
3. **Реактивность хранилища:** При отправке текста из `background.js` в `sidepanel.js` всегда добавляй уникальную метку времени: `{ selectedText, timestamp: Date.now() }`. Иначе событие `chrome.storage.onChanged` не триггерится, если юзер выделит тот же самый текст повторно.
4. **UX и целостность логики:** Всегда защищай интерфейс от race conditions (повторные запросы во время ожидания fetch). Управляй фокусом, состояниями кнопок и сбросом скролла при обновлении контента.
5. **Разумная модульность:** Жёстких лимитов на количество файлов больше нет. Развивай архитектуру логично. Если нужен новый service-файл, локальный скрипт санитизации или отдельный модуль для API — создавай их, но сохраняй общую минималистичность Vanilla JS.
6. **Стиль работы:** Пиши код и решай проблему только в рамках текущего промпта. Предлагай точечные, элегантные решения. Не переписывай рабочие куски системы без явной команды.
